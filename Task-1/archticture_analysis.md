# Проблемные места  и приоритизация

## Проблемные места

### Устаревшие технологии
SQL Server 2008, Power Builder - устаревшие и создают проблемы безопасности, отсутствие поддержки, сложность найма и обучения сотрудников.

### Монолитная архитектура DWH
Вся бизнес логика сосредоточена в одном DWH - дает сложность в изменениях, блокировки при разработке. От этого медленный ttm, высокие затраты на разработку.

### Производительнолсть
Сложные отчеты выполняются часами. Аналитика становится неэффективной, создаются задержки в принятии решений.

### Отсутствие разделения доменов
Все данные смешаные в одном хранилище, сложно независимо развивать бизнес.

### Сложность интеграций
Статичная шина на Apache Camel, сложно добавлять новые источники данных, от этого медленная интеграция новых компаний.

## Приоритизация проблем (MoSCow)
### MUST HAVE
1. Миграция с SQL Server 2008 - риски безопасности и отсутствие поддержки
2. Создание портала самообслуживания - основное требование бизнеса
3. Разделение на домены - необходимость независимого развития
4. Внедрение Data Lakehouse - решение проблем производительности

### SHOULD HAVE
1. API Gateway - стандартизация интеграций
2. Event Streaming - real time обработка данных
3. Централизованное управление доступом - безопасность

### COULD HAVE
1. Service Mesh - управление микросервисами
2. Расширенный мониторинг - наблюдаемость системы
3. Автоматизация тестирования - качество разработки
4. CI/CD пайплайны - скорость разработки

### WON'T HAVE
1. Полная замена Power BI - можно оставить на переходный период
2. Миграция всех легаси-систем - поэтапный подход
