# Технический радар и роадмап

## Технический радар

### ADOPT (Принять) - Готовые к использованию
**Языки и фреймворки:**
- Java 17 - основной язык для медицинского домена
- Python 3.11 - для аналитики и ИИ
- Golang 1.21 - для финтех домена
- TypeScript 5.0 - для фронтенда
- React 18 - для веб-интерфейсов

**Инструменты:**
- Docker - контейнеризация
- Kubernetes - оркестрация контейнеров
- Git - система контроля версий
- Gradle - сборка Java проектов

**Платформы:**
- PostgreSQL 17 - реляционная БД
- MinIO - S3-совместимое хранилище
- Apache Kafka - event streaming
- Nginx - веб-сервер и балансировщик

**Методы:**
- Agile/Scrum - методология разработки
- CI/CD - непрерывная интеграция и доставка
- API-first - подход к разработке API
- Microservices - архитектурный подход

### TRIAL (Пробовать) - Экспериментальные
**Языки и фреймворки:**
- FastAPI - для Python API
- Spring Boot 3 - для Java микросервисов

**Инструменты:**
- Apache Airflow - оркестрация ETL/ELT
- Dremio - data lake query engine
- Grafana - мониторинг и визуализация
- DataHub - каталог данных

**Платформы:**
- Apache Iceberg - table format для Data Lakehouse
- Redis - кэширование
- Elasticsearch - поиск и аналитика

**Методы:**
- Data Mesh - архитектурный подход
- Event Sourcing - паттерн хранения событий
- Domain-Driven Design - проектирование доменов

### ASSESS (Оценивать) - Перспективные

**Инструменты:**
- Apache Hudi - альтернатива Iceberg
- Delta Lake - table format от Databricks
- Apache Druid - аналитическая БД

**Платформы:**
- Apache Flink - stream processing
- Apache Spark - big data processing
- ClickHouse - аналитическая БД

### HOLD (Удерживать) - Не использовать
**Языки и фреймворки:**
- Power Builder - устаревшая технология

**Инструменты:**
- SQL Server 2008 - устаревшая версия

**Платформы:**
- Windows Server 2008 - устаревшая ОС


## Роадмап технологических изменений

### Этап 1: Подготовка инфраструктуры (0-3 месяца)
**Цели этапа:**
- Создание современной инфраструктуры
- Миграция с устаревших технологий
- Настройка CI/CD пайплайнов

### Этап 2: Создание доменов (3-6 месяцев)
**Цели этапа:**
- Выделение доменов из монолита
- Создание API для каждого домена
- Настройка межсервисной коммуникации

### Этап 3: Data Lakehouse (6-9 месяцев)
**Цели этапа:**
- Создание современного хранилища данных
- Миграция данных из DWH
- Настройка каталога данных

### Этап 4: Портал самообслуживания (9-12 месяцев)
**Цели этапа:**
- Создание портала для аналитиков
- Интеграция с BI-инструментами
- Настройка мониторинга

### Этап 5: Оптимизация и масштабирование (12-18 месяцев)
**Цели этапа:**
- Оптимизация производительности
- Масштабирование системы
- Внедрение новых технологий

## Обоснование изменений

### 1. Миграция с SQL Server 2008
- Активная поддержка сообщества
- Современные возможности (JSON, полнотекстовый поиск)
- Лучшая производительность

### 2. Внедрение Data Lakehouse
- ACID-транзакции
- Поддержка различных форматов данных
- Масштабируемость
- Версионирование

### 3. Разделение на домены
- Независимое развитие
- Масштабируемость
- Отказоустойчивость

### 4. Портал самообслуживания
- Снижение времени создания отчётов
- Улучшение пользовательского опыта
